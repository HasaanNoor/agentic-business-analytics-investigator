# ADR 0001: Deterministic Analysis Before LLM Reasoning

- Status: Accepted
- Date: 2026-08-04

## Context

Agentic Business Analytics Investigator works with operational ecommerce signals: KPI summaries, anomaly events, incident reports, forecasts, SHAP feature importance, historical incident retrieval, and multi-agent investigation reports. These outputs must be testable and explainable because the project is about analytics, not only narrative generation.

The repository already separates the analytical pipeline from optional LLM synthesis. KPI monitoring and anomaly detection are deterministic Python steps. Forecasting produces explicit model outputs. Explainability writes SHAP feature importance when available and a clear fallback explanation when SHAP cannot be produced cleanly. Historical incident retrieval builds and queries a local knowledge base. The multi-agent investigation workflow loads structured inputs from the investigation report, KPI summary, deployment events, forecast summary, SHAP feature importance, and retrieved historical incidents before producing final reports.

LLM behavior is optional. The executive report can call OpenAI when `OPENAI_API_KEY` is set, but it builds a structured evidence bundle first and has a deterministic fallback report. Multi-agent investigation supports deterministic, LLM, and auto modes, with fallback behavior controlled through configuration. CI disables LLM mode so tests do not require credentials or external model calls.

## Decision

Run deterministic analytics before optional LLM reasoning. Anomaly detection, forecasting, SHAP explainability, evidence retrieval, and structured investigation inputs are produced before any LLM synthesis path. Deterministic behavior remains available as the default or fallback path.

LLMs are used for synthesis, interpretation, and specialist-agent phrasing over existing evidence. They are not the sole source of analytical truth. Prompts and schemas must stay grounded in the structured outputs that the deterministic pipeline already produced.

## Alternatives considered

Sending raw operational data directly to one general-purpose LLM would reduce orchestration code, but it would make results harder to reproduce, test, and trace. It would also blur the distinction between measured evidence, model output, and generated interpretation.

Making the LLM path mandatory would simplify mode selection, but local development, CI, and offline review would depend on external credentials, network access, and model availability. It would also make failures in an optional reasoning layer capable of blocking the whole investigation workflow.

Using only deterministic reports with no optional LLM synthesis would maximize reproducibility and cost control. The downside is that it would avoid demonstrating how language models can turn structured evidence into clearer summaries, specialist perspectives, and executive-facing narratives.

## Consequences

Positive consequences:

- Reproducibility improves because the core analytical artifacts are generated by deterministic code and fixed inputs.
- Tests can validate the pipeline, API responses, database fallback behavior, and frontend views without OpenAI access.
- Traceability improves because reports can point back to KPI rows, anomaly events, forecast outputs, SHAP drivers, retrieved historical incidents, and provenance fields.
- Resilience improves because deterministic fallback remains available when LLM configuration is missing or an LLM call fails.
- LLM output is constrained to synthesis over evidence rather than unbounded analysis over raw data.

Negative consequences:

- The system has more interfaces and orchestration points than a single LLM prompt.
- Deterministic and LLM paths both require tests to avoid drift.
- The LLM has less flexibility because it must stay inside the evidence bundle, schema, and prompt constraints.
- Some narrative improvements require changes to both evidence preparation and LLM prompts.

## When to revisit

Revisit this decision if the project introduces a reliable analytical engine that can provide equivalent reproducibility, provenance, and testability through another architecture. Also revisit if live production users require interactive reasoning that cannot be expressed through the current structured evidence boundary, or if deterministic and LLM paths diverge enough that maintaining both no longer provides clear value.
